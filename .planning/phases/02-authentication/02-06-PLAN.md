## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet client -> auth endpoints | Unauthenticated, high-volume input |
| proxy -> uvicorn | Which hop's address counts as the client IP |
| app -> Resend quota | Every accepted request-code costs an email |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-32 | Spoofing | OTP brute force across many codes | mitigate | Verify limits per email (10/10 min) and per IP (30/10 min) on top of the 5-attempt kill; tests |
| T-02-33 | Denial of service | email bombing a victim / quota exhaustion | mitigate | Request limits per email (5/10 min), per IP (20/h), global (500/day); no code issued or sent on 429 |
| T-02-34 | Spoofing | forged X-Forwarded-For to dodge per-IP limits | mitigate | App reads only `request.client.host`; uvicorn trusts forwarded headers only from `--forwarded-allow-ips` (default 127.0.0.1, asserted in a test); XFF ignored test |
| T-02-35 | Denial of service | Redis keys without TTL filling a noeviction instance | mitigate | INCR + EXPIRE NX + TTL in one MULTI; test asserts TTL > 0 on every sim:rl:* key |
| T-02-36 | Information disclosure | enumeration via 429 differences | mitigate | Identical 429 body for existing/new emails; limits keyed by HMAC of the email |
| T-02-37 | Denial of service | attacker burns a victim's per-email quota | accept | Fixed-window nuisance lockout for at most 10 minutes; acceptable for a friends-only app; documented in code |
</threat_model>

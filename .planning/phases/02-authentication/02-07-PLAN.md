<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> POST /auth/refresh | Long-lived bearer secret presented by the client |
| browser -> POST /auth/logout | Must end the session even with an expired access token |
| tab A <-> tab B | Two tabs share one cookie jar and race on refresh |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-38 | Spoofing | stolen refresh token replay | mitigate | Rotation on every use; reuse beyond the 10 s grace revokes the whole session (family); tests for replay, revoked and expired tokens |
| T-02-39 | Tampering | concurrent rotation of one token | mitigate | `SELECT ... FOR UPDATE` serializes; loser sees used_at within grace -> 401 without revoke; concurrency test |
| T-02-40 | Elevation of privilege | session survives sign-out | mitigate | Logout sets `revoked_at` via the access cookie's sid (decoded with verify_exp=False, signature still verified); `get_current_user` checks revoked_at on every request; test: old cookie -> 401 immediately |
| T-02-41 | Tampering | CSRF-forced logout or refresh | mitigate | Both POSTs require the double-submit CSRF header; SameSite=Strict; 403 tests |
| T-02-42 | Denial of service | refresh loops in the client | mitigate | No refresh for /api/v1/auth/* paths; single retry; single-flight promise; unit tests |
| T-02-43 | Information disclosure | refresh cookie exposure | mitigate | Refresh cookie HttpOnly, Secure, SameSite=Strict, Path=/api/v1/auth/refresh only; only its sha256 is stored |
| T-02-44 | Repudiation | expired refresh rows accumulate | accept | Rows are hashes with expiry; cleanup job is v2 (RESEARCH Schema note) |
| T-02-54 | Elevation of privilege | logout without an access cookie (cookie deleted or browser cleared it) | accept | The server cannot identify the session, so it is not revoked; logout still clears all cookies, so the client loses the refresh token, and the session expires with its refresh token (<= 30 days). No design change; noted in 02-07-SUMMARY.md |
</threat_model>

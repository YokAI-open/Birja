## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-26 | Information disclosure | token storage in the browser | mitigate | No localStorage/sessionStorage; auth tokens only in HttpOnly cookies set by the server; grep check in acceptance criteria |
| T-02-27 | Tampering | XSS through rendered email or messages | mitigate | React default escaping only; no `dangerouslySetInnerHTML`; error text comes from a fixed client-side map, not raw server HTML |
| T-02-28 | Tampering | CSRF from the SPA | mitigate | apiFetch always adds `X-CSRF-Token` on non-GET, fetching `/auth/csrf` first when missing |
| T-02-29 | Information disclosure | account enumeration through UI copy | mitigate | Identical "We sent a code" step and generic invalid-code copy regardless of account existence |
| T-02-30 | Elevation of privilege | e2e code retrieval | mitigate | Code read from `docker compose logs` with `execFileSync` (no shell, fixed argv); no debug route exists in the app |
| T-02-31 | Tampering | money precision in the UI | mitigate | Strings formatted with Intl.NumberFormat, never parsed to float; 18-digit test case |
</threat_model>

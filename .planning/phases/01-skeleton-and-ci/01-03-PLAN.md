## Phase Goal

**As a** developer, **I want to** start the whole YokaiExchange stack with one command and have every PR checked automatically, **so that** each later feature is built on a running, guarded base and a failing change cannot slip into `develop`/`main`.

<objective>
Extend the backend slice into Docker Compose: after this plan `cp .env.example .env && docker compose up --build` brings up Postgres, Redis and the backend, the backend migrates to the Alembic baseline (the skeleton's real DB write) and `curl http://127.0.0.1:8000/api/v1/health` reports both dependencies reachable.

Purpose: The compose stack and Dockerfile are the base that the frontend joins in plan 06 and that CI builds in plan 07. The baseline migration is kept on purpose: CLAUDE.md requires every schema change to be a migration, and an empty baseline establishes that rule cheaply without inventing a domain table (CLAUDE.md forbids speculative models).
Output: Alembic async setup + baseline, `Base` with naming convention, backend Dockerfile, compose + dev override, `.env.example`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host / LAN -> compose services | Only explicitly published ports are reachable |
| backend container -> postgres/redis | Internal `data` network, password-authenticated |
| .env -> containers | Secrets enter through environment interpolation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09 | Elevation of Privilege | docker-compose.yml postgres/redis | mitigate | No `ports:` for postgres/redis; they sit only on the `internal: true` `data` network; dev override publishes backend on 127.0.0.1 only |
| T-01-10 | Spoofing | redis | mitigate | `--requirepass ${REDIS_PASSWORD}`; healthcheck uses REDISCLI_AUTH env, not `-a` |
| T-01-11 | Information Disclosure | .env / .env.example | mitigate | `.env` git-ignored (verified with git check-ignore); `.env.example` holds placeholders only; compose fails fast via `${VAR:?}` when unset |
| T-01-12 | Elevation of Privilege | backend container | mitigate | runtime stage runs as `app` (uid 1001); pinned base images; runtime copies only app/, alembic/, alembic.ini |
| T-01-13 | Tampering | image build | mitigate | `uv sync --locked` fails on a stale lock; uv image pinned to 0.13.5 |
| T-01-14 | Information Disclosure | redis command line | accept | Password visible in the container's own process list; container is single-purpose and not shared. Revisit with a config file in Phase 6 hardening |
| T-01-15 | Denial of Service | redis memory | mitigate | `maxmemory 256mb` + `noeviction` per CLAUDE.md; Phase 1 writes no keys |
| T-01-16 | Elevation of Privilege | Postgres superuser role | accept | Dev stack uses the image's default superuser; least-privilege app role + SSL are Phase 6 (RESEARCH Security Domain) |
</threat_model>

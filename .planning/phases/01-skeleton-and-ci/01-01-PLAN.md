## Phase Goal

**As a** developer, **I want to** start the whole YokaiExchange stack with one command and have every PR checked automatically, **so that** each later feature is built on a running, guarded base and a failing change cannot slip into `develop`/`main`.

<objective>
Put the phase on its own git-flow feature branch, then gate it on the two things only the human can do: install the local toolchain (uv, Node 24) and confirm the package list is legitimate before any `uv add` / `npm install` runs.

Purpose: Every later plan runs `uv` and `npm` on the host. `docker compose up --build` itself never depends on these tools (everything builds in containers), but scaffolding, lockfile generation, lint and tests do. The package-legitimacy gate is required because RESEARCH.md could not run slopcheck, so every package is treated as `[ASSUMED]`.
Output: No files. The feature branch `feature/phase-01-skeleton-and-ci`, a confirmed toolchain and an approved package list that plans 02-07 install from.
</objective>

<decisions>
## Implementation Decisions

### Address
- **D-01:** Birja lives at **https://birja.nist.one**. The existing static page at nist.one (`/var/www/nist.one`, nginx site `nist.one`) stays untouched. The phase goal and success criteria in ROADMAP.md say "https://nist.one" and must be read as birja.nist.one.

### Deploys
- **D-02:** Deploys are a **manual script on the server** (e.g. `./deploy.sh`): pull `main`, build, migrate, restart, health-check. There is no CI auto-deploy and no SSH keys in GitHub.

### TLS and Cloudflare
- **D-03:** Cloudflare SSL/TLS mode for nist.one is **Full (strict)**, as the user reported. The origin certificate must be valid. The current ZeroSSL `*.nist.one` certificate (SAN `*.nist.one`, `nist.one`) at `/root/.acme.sh/*.nist.one_ecc/` **expired 2026-10-21**, so renewing it is a prerequisite.
- **D-04:** There is **one scoped Cloudflare API token** (Zone → DNS → Edit, nist.one only). The user creates it and writes it into the root-only file `/root/.secrets/cloudflare.env` (chmod 600) **themselves** at a checkpoint. It is never pasted into chat, committed, logged or echoed.
  - acme.sh is switched from manual DNS mode to `dns_cf`, using this token for unattended renewal from the existing cron entry.
  - Claude creates the DNS record `birja` → A `151.243.171.52`, proxied, through the Cloudflare API. Claude reads the token from that file without printing it.
  - No Cloudflare MCP is installed (user asked; declined in favor of the token).

### Release to main
- **D-05:** `main` has no app yet (it is at 91deb8b). Before the first prod deploy, the phase follows git-flow from CLAUDE.md:
  - Create `release-0.1` from `develop` and open a PR into `main`. The user approves it, `ci-pass` is green, and it is merged with "Create a merge commit".
  - Tag `v0.1.0` on `main`, then merge `release-0.1` back into `develop` by PR.
  - Every push and merge needs the user's explicit approval.
  - `deploy.sh` deploys `main` by default and accepts a ref override (`DEPLOY_REF`, e.g. a tag).

### No Cloudflare automation
- **D-06:** No cron jobs or scheduled automation touch Cloudflare, the nginx real-IP list or ufw.
  - The Cloudflare IP list for nginx `real_ip` is generated once by a script, with a documented manual refresh command.
  - ufw is not modified. Its current 80/443 allow-list already matches Cloudflare's ranges.
- **D-07:** Certificate renewal is **manual**. This **overrides D-04's "unattended renewal" part.**
  - Use the token once now to re-issue the expired `*.nist.one` + `nist.one` ZeroSSL ECC certificate via `dns_cf`, and install it to a stable nginx path.
  - Leave no automatic renewal running. Disable or neutralize the acme.sh cron entry for this cert, or record exactly what stays.
  - Document the renewal command in a runbook, and record the next expiry date and when to renew (about 30 days before).
  - ROADMAP success criterion 4 is now "renewal procedure documented and executed once".
  - D-04's DNS-record creation by Claude through the API still applies.

### Claude's Discretion
- Prod compose layout (separate project name, env file, volumes, ports bound to 127.0.0.1), the frontend prod build served by host nginx, uvicorn worker settings, and how real client IPs survive Cloudflare → nginx → uvicorn for the per-IP rate limits all follow RESEARCH.md and CLAUDE.md.
- Phase 2 review items IN-03 (dev codes in public CI logs on e2e failure) and IN-04 (`ENV` defaults to dev) are in scope. So is caching Playwright browsers in CI.

</decisions>

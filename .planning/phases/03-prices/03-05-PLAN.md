## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Kraken/fake source -> scheduler cycle | External price data is evaluated before it is written |
| scheduler -> Redis | Lock state (rebuildable, TTL'd) |
| scheduler -> Postgres | Writes the prices other users and Phase 4 rely on |
| configuration -> runtime | PRICE_SOURCE selects real vs fake data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-17 | Tampering / Elevation | fake price source in production | mitigate | Settings model validator refuses `price_source=fake` when `env=prod` (tested); `build_source` re-checks and raises; no HTTP route exposes it; prod compose hardcodes `PRICE_SOURCE: "kraken"` (03-08) |
| T-03-18 | Tampering | bad prices overwriting good ones | mitigate | evaluate_price per coin; rejected observations never write; upsert guarded by `as_of < excluded.as_of`; DB CHECK mid > 0; tests assert row and as_of unchanged |
| T-03-19 | Tampering / DoS | two concurrent refreshers | mitigate | Redis `SET NX PX 45000` lock with random token and Lua compare-and-delete in finally; skip cycle when held or when Redis errors (fail closed, prices age visibly; RESEARCH A9 accepted) |
| T-03-20 | Information disclosure | scheduler logs | mitigate | Log only symbols, reasons, counts and Kraken error strings; never env, credentials or response bodies |
| T-03-21 | Repudiation | which source wrote a price | mitigate | `prices.source` column (CHECK kraken/fake) written on every upsert |

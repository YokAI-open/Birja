## Accomplishments

- HistoryPage flattens real server pages in order with unchanged string ID keys and complete desktop/mobile fields. Load more disables during any history fetch and uses the existing opaque next cursor. An additional `cancelRefetch: false` prevents duplicate append requests during rapid repeated activation. Initial errors, retained background errors and next-page failures remain distinct; failed append preserves rows and retries the identical boundary.
- One atomic polite status announces loading, append counts and the visible total. The primary control exposes Load more, Loading more trades… and Try loading more. Exhaustion alone reveals All trades loaded. A stable callback ref detects whether the removed button actually owned focus, and only then transfers it to the nearby `tabIndex=-1` marker with `preventScroll`. Appended rows never receive focus; moving focus elsewhere during the request is respected.
- The existing useHistory implementation already refetches stale loaded pages sequentially with TanStack. Real hook tests demonstrate three-page traversal, focus refetch after newer fills, newly returned cursor boundaries instead of stale cursor reuse, and retention of the entire previous chain when a later refresh page fails. It remains unpolled, abortable and free of manual page/cursor arrays.
- Trade metadata declares `ix_trades_user_created_id (user_id, created_at, id)`. Revision 0008 was actually autogenerated on isolated PostgreSQL at 0007, then reviewed into index-only concurrent create/drop inside autocommit blocks. Online and offline Alembic use `transaction_per_migration=True`. No historical migration was edited and no rows are rewritten.
- Real populated migration tests preserve complete users/accounts/holdings/trades rows and all account/holding/trade constraints across 0007→0008→0007→head. They inspect `indisvalid`, `indisready`, exact `pg_get_indexdef` and catalog key order, verify index absence after downgrade, and retain full base roundtrip plus metadata parity. A separate failed-0007 test proves preceding 0006 stays committed under per-revision transactions. The original targeted 0007 sub-cent refusal and 0006→0007 assertions remain intact.
- RUNBOOK documents the named index/revision/validity inspection, checking for an active concurrent build, reviewing and dropping only a failed invalid new index outside a transaction, and rerunning normal migrations. It explicitly rejects silent stamping and `IF NOT EXISTS` masking.

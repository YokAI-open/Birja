## Summary

The host is closer to ready than the brief assumed. Verified by inspection: ufw is active with default-deny INPUT, 22 open, and 80/443 allowed **only from the current Cloudflare ranges** (the ufw list is byte-identical to Cloudflare's published `ips-v4`/`ips-v6` today). nginx 1.24.0 is installed, disabled and inactive; ports 80/443 are free; Docker is enabled at boot; acme.sh v3.1.5 and the ZeroSSL account exist, and the `*.nist.one` ECC cert has `Le_Webroot='dns'`. `/root/.secrets` does not exist yet. `jq`, `dig`, `nmap` are not installed (only `openssl`, `curl`, `git`). The existing `nist.one` site is down at the origin right now (nginx inactive, cert expired), so enabling nginx also revives it.

Two findings change the plan. (1) **`main` is at "Add base files" (91deb8b)**: it contains none of Phases 1-2. D-02's "pull `main`" cannot deploy anything until a `release-*` merge puts the app on `main` (git-flow, via PR). The deploy script needs a configurable ref (default `main`) and the plan needs an explicit "release to main" step/checkpoint before the first real deploy. (2) **Client IP**: the backend (`get_client_ip`) trusts only the socket peer; behind Docker's published port the peer is the bridge gateway, so every user would share one rate-limit bucket. The fix is nginx `real_ip` from Cloudflare, nginx overwriting `X-Forwarded-For` with `$remote_addr`, and uvicorn `--proxy-headers --forwarded-allow-ips <pinned prod bridge subnet>`. The ufw Cloudflare allow-list makes the chain unspoofable.

**Primary recommendation:** Host nginx (sole public entry) serves a symlinked Vite `dist` release dir and proxies `/api/` to a 127.0.0.1-bound backend of a standalone `docker-compose.prod.yml` (project `birja-prod`, env file `/etc/birja/prod.env`); certs are re-issued once via `acme.sh --issue --dns dns_cf` (same `-d` order, so the `*.nist.one_ecc` dir is reused) and installed to `/etc/nginx/certs/nist.one/` with a `reload-or-restart nginx` hook; everything is driven by one idempotent `deploy/deploy.sh`.

### 1. acme.sh: manual DNS -> dns_cf (Q1)

- acme.sh stores `CF_Token` (and `CF_Account_ID`/`CF_Zone_ID`) automatically on first successful use. [VERIFIED: local `/root/.acme.sh/dnsapi/dns_cf.sh` lines 24-39] If `CF_Zone_ID` is exported, the values go to the **per-cert domain conf** (`_savedomainconf`); otherwise to `account.conf` (`_saveaccountconf_mutable`). Both are root-only (`account.conf` is mode 600 [VERIFIED]); the cert conf is 600 too [VERIFIED]. Plaintext at rest, root-only: accepted, say so in the plan.
- The cert is in manual mode (`Le_Webroot='dns'`), so `--renew` would demand the manual-DNS flag. Re-issue instead, **keeping the same `-d` order** (`'*.nist.one'` first) so acme.sh keeps using the existing `*.nist.one_ecc` directory (the untouched `nist.one`/`lib.nist.one` nginx sites point there and keep working after re-issue):
```bash
set -a; . /root/.secrets/cloudflare.env; set +a        # exports CF_Token (+ CF_Zone_ID); never echo
/root/.acme.sh/acme.sh --issue --dns dns_cf -d '*.nist.one' -d nist.one \
  --keylength ec-256 --server zerossl --force
```
  (`--force` is needed because the saved Le_Webroot/expiry state; once it succeeds, `Le_Webroot` becomes `dns_cf`.) [CITED: acme.sh wiki "dnsapi" - dns_cf usage; ASSUMED for exact flag combo on an existing manual cert - confirm output shows `Le_Webroot='dns_cf'` afterwards via `grep Le_Webroot` on the conf file (a non-secret line)]
- Install to a stable path, with reload (the hook is saved and re-run on every renewal):
```bash
install -d -m 750 /etc/nginx/certs/nist.one
/root/.acme.sh/acme.sh --install-cert --ecc -d '*.nist.one' \
  --key-file /etc/nginx/certs/nist.one/key.pem \
  --fullchain-file /etc/nginx/certs/nist.one/fullchain.pem \
  --reloadcmd "systemctl reload-or-restart nginx"
chmod 600 /etc/nginx/certs/nist.one/key.pem
```
  `reload-or-restart` (not `reload`) so it also succeeds while nginx is still inactive during the first run.
- **Token scope caveat:** `dns_cf` looks up the zone via `GET zones?name=...` unless `CF_Zone_ID` is set; listing zones needs **Zone -> Zone -> Read**, and `GET zones/<id>` is also called when `CF_Zone_ID` is set (dns_cf.sh line 170). Ask the user to create the token with **Zone:DNS:Edit + Zone:Zone:Read, restricted to the nist.one zone**, and to also put `CF_Zone_ID=<32-hex>` (non-secret, visible in the dashboard overview) in the env file. [CITED: CF token docs list DNS Edit; Zone Read requirement ASSUMED - verify with the check below]
- **Env file format** (`/root/.secrets/cloudflare.env`, 600): lines `CF_Token=...` and `CF_Zone_ID=...`, no spaces/quotes, so it can be sourced by both bash and acme.sh. `/root/.secrets` dir mode 700.
- **Pre-flight (no CA call, no rate-limit cost):** `curl -K` verify (below) `GET /client/v4/user/tokens/verify` -> `"status":"active"` and `GET /zones/$CF_Zone_ID/dns_records?per_page=1` -> success.
- **Rate limits / testing:** ZeroSSL's own page claims no ACME rate limits; third-party sources claim a free-plan cap of 3 active 90-day certs and the existence of a `.../DV90/staging` endpoint - **neither confirmed in ZeroSSL docs** [LOW]. Policy: no loop of forced issues. Do exactly one `--issue --force` (success criterion 4's "forced renewal succeeds" *is* this run plus one more `--renew --force --ecc` at most, after which `--list` shows a future `Le_NextRenewTime`). Re-run only after reading the error.
- **Cron:** the existing entry (`4 2,8,14,20 * * * acme.sh --cron`) is sufficient; output goes to /dev/null so failures are silent. Smoke script should check `openssl x509 -checkend $((20*86400))` on the installed cert, and the plan should add an optional `--log /var/log/acme.sh.log` note (cron edit = user-visible change; ask or leave).

### 2. Cloudflare DNS record (Q2)

Token read without echo, not visible in `ps` (curl config via process substitution), no `set -x`:
```bash
set -a; . /root/.secrets/cloudflare.env; set +a
cf() { curl -sS -K <(printf 'header = "Authorization: Bearer %s"\n' "$CF_Token") \
         -H 'Content-Type: application/json' "$@"; }
API=https://api.cloudflare.com/client/v4
# zone id: use CF_Zone_ID if provided, else GET $API/zones?name=nist.one (needs Zone:Read)
existing=$(cf "$API/zones/$CF_Zone_ID/dns_records?type=A&name=birja.nist.one")
# parse with python3 -I -c (no jq): id, content, proxied
# none -> POST   {"type":"A","name":"birja","content":"151.243.171.52","proxied":true,"ttl":1}
# exists but content/proxied differ -> PATCH $API/zones/$CF_Zone_ID/dns_records/<id>
# exists and identical -> no-op
```
`ttl: 1` means automatic (required for proxied records). Check-then-create/PATCH is idempotent. Verify: re-GET the record (`proxied:true`), and resolve through DoH (no `dig`): `curl -s -H 'accept: application/dns-json' 'https://1.1.1.1/dns-query?name=birja.nist.one&type=A'` -> must return Cloudflare IPs, **not** 151.243.171.52 (proves proxied). [ASSUMED standard CF behaviour; DoH endpoint is Cloudflare's documented one.]
- **Full (strict) requires:** origin presents a cert that is unexpired, chains to a public CA (or CF Origin CA) and whose SAN covers the requested host (`*.nist.one` covers `birja.nist.one`). Expired cert => Cloudflare 526. The edge cert for birja.nist.one: Universal SSL covers `nist.one` and one-level `*.nist.one` [ASSUMED standard; verify with `openssl s_client -connect birja.nist.one:443 -servername birja.nist.one`].
- Error-code cheat sheet for the plan: 521 = origin refused (nginx down / ufw), 525 = TLS handshake failed, 526 = invalid origin cert.

### 3. Real client IP (Q3)

Chain: only Cloudflare can reach 443 (ufw), so every nginx peer is a CF IP; Cloudflare sets `CF-Connecting-IP`.

- nginx (scoped inside the birja server block via an include so the untouched nist.one site is not affected):
```nginx
# /etc/nginx/snippets/birja-cloudflare-realip.conf  (generated by deploy/cloudflare-ips.sh)
set_real_ip_from 173.245.48.0/20;   # ... all of https://www.cloudflare.com/ips-v4 and ips-v6
real_ip_header CF-Connecting-IP;
real_ip_recursive off;
```
  Generator: `curl -fsS` the two lists, validate every line with a strict CIDR regex, abort without touching the file if either fetch fails or yields zero lines, write to temp, `nginx -t`, then `systemctl reload nginx`. Run it from deploy.sh and a monthly cron. [Cloudflare publishes the lists at the two URLs above - VERIFIED reachable, 15 v4 + 7 v6 ranges today.]
- nginx -> backend: **overwrite**, never append:
  `proxy_set_header X-Forwarded-For $remote_addr; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-Proto $scheme;` ($remote_addr is already the real client after `real_ip`).
- uvicorn: `--proxy-headers --forwarded-allow-ips 172.29.50.0/24`. The published-port peer seen by the container is the prod bridge gateway (dev bridge is 172.18.0.1 [VERIFIED]); **pin the prod `app` network subnet** in compose (`ipam: config: [{subnet: 172.29.50.0/24}]`) so the trust range is deterministic. Do NOT use `*`. Only nginx can reach `127.0.0.1:18000`, and postgres/redis are not on the `app` network, so trusting the subnet is safe. `get_client_ip` needs **no code change** (its comment already anticipates `--proxy-headers`).
- **Verification (must be a task):** after deploy, request code 3 times with a spoofed `X-Forwarded-For: 1.2.3.4` and `CF-Connecting-IP: 1.2.3.4` header from the host through `--resolve ...:127.0.0.1` -> the loopback peer is not a CF range, so `CF-Connecting-IP` must be ignored; confirm in a unit/integration check (or by logging `$remote_addr` in a temp access-log format) that nginx logs 127.0.0.1, not 1.2.3.4. Also confirm the backend bucket key differs per real client (Redis key inspection via `redis-cli --scan`, never print codes).
- **Origin allow-list:** already enforced by ufw (verified identical to CF lists). Gaps to flag: (a) nothing keeps the ufw list current - a new CF range would be silently blocked (availability, not security); extending `cloudflare-ips.sh` to sync ufw is a firewall change -> ask the user (Open Question 4). (b) Docker-published ports bypass ufw, which is why every published port is bound to 127.0.0.1. Do not add an nginx `allow/deny` on top (redundant, and breaks the `--resolve` local smoke tests).
- IPv6: the record is A-only, CF connects over IPv4; the app already groups IPv6 by prefix.

Generates `POSTGRES_PASSWORD`, `REDIS_PASSWORD` (hex, letters/digits only - they sit in URLs), `OTP_HMAC_SECRET`, `JWT_SECRET` (distinct, `openssl rand -hex 32`), `POSTGRES_USER=birja`, `POSTGRES_DB=birja`; leaves `RESEND_API_KEY=` empty and `EMAIL_FROM=` for **the user** to fill (human checkpoint). `EMAIL_FROM` needs double quotes in the env file (`"Birja <login@domain>"`). deploy.sh must fail fast if either is empty. ### 5. Frontend: host-nginx static vs container (Q5) - recommend host static

`deploy.sh` step:
```bash
REL=/var/www/birja/releases/$(git rev-parse --short HEAD)-$(date -u +%Y%m%dT%H%M%SZ)
```

### 6. nginx site (Q6)

nginx here is **1.24**: use `listen 443 ssl http2;` (the `http2 on;` directive needs >= 1.25.1). Mirror the existing site's TLS block (TLSv1.2/1.3, same cipher list, `ssl_prefer_server_ciphers off`, `ssl_ecdh_curve secp384r1`, session cache, tickets off). Exact `server_name birja.nist.one` wins over the existing `*.nist.one` wildcard server blocks (exact beats wildcard) - verify with `nginx -T` and a curl after reload. No `default_server` conflict: `default` owns `listen 80 default_server` only; 443 has none (unknown hosts on 443 fall to the first 443 server, `nist.one` - existing behaviour).
```nginx
limit_req_zone $binary_remote_addr zone=birja_auth:10m rate=30r/m;   # http context: put in conf.d/birja-zones.conf
limit_req_status 429;   # inside server

server { listen 80; listen [::]:80; server_name birja.nist.one; return 301 https://birja.nist.one$request_uri; }

server {
  listen 443 ssl http2; listen [::]:443 ssl http2;
  server_name birja.nist.one;
  server_tokens off;
  include /etc/nginx/snippets/birja-cloudflare-realip.conf;
  ssl_certificate     /etc/nginx/certs/nist.one/fullchain.pem;
  ssl_certificate_key /etc/nginx/certs/nist.one/key.pem;
  # protocols/ciphers/session settings copied from /etc/nginx/sites-available/nist.one
  gzip on; gzip_types text/css application/javascript application/json image/svg+xml; gzip_min_length 1024;
  client_max_body_size 16k;                       # JSON auth bodies only
  root /var/www/birja/current;
  include /etc/nginx/snippets/birja-security-headers.conf;

  location /assets/ { try_files $uri =404;        # hashed files; a miss must NOT fall back to index.html
    add_header Cache-Control "public, max-age=31536000, immutable" always;
    include /etc/nginx/snippets/birja-security-headers.conf; }
  location = /index.html { add_header Cache-Control "no-cache" always; include .../birja-security-headers.conf; }
  location /api/v1/auth/ { limit_req zone=birja_auth burst=20 nodelay; include .../birja-proxy.conf; proxy_pass http://127.0.0.1:18000; }
  location /api/ { include .../birja-proxy.conf; proxy_pass http://127.0.0.1:18000; }   # no URI part => path preserved
  location / { try_files $uri /index.html; }
  location ~ /\. { deny all; }
}
```
- **`add_header` inheritance pitfall:** any `add_header` inside a `location` discards all server-level `add_header`s. Put every security header in one snippet and `include` it in each location that sets its own `add_header` (HSTS/CSP silently vanishing on `/assets/` is the classic bug; smoke test must check headers on `/`, `/assets/*.js`, and `/api/v1/health`).
- Headers (snippet): `Strict-Transport-Security "max-age=63072000; includeSubDomains"` (no `preload`; existing site uses 63072000 without subdomains), `X-Content-Type-Options nosniff`, `X-Frame-Options DENY`, `Referrer-Policy strict-origin-when-cross-origin`, `Permissions-Policy` optional, and CSP:
  `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'`.
  Basis: built `index.html` has a single external module script, no inline script/style [VERIFIED: grep of `frontend/dist/index.html`]; Inter is bundled via fontsource into `/assets` (so `font-src 'self'`). `style-src 'unsafe-inline'` is kept because Radix/shadcn can inject inline `style` at runtime [ASSUMED] - the plan must run the Playwright e2e/browser console against the prod build and tighten only if there are zero violations. Start enforcing (not Report-Only); the check is the browser-console task.
- `limit_req` interplay: nginx limit is a coarse per-real-IP flood guard (30 req/min, burst 20; the SPA's page load does csrf + refresh + me under `/api/v1/`). App limits (5 codes/10 min/email, 20 code requests/h/IP, 30 verifies/10 min/IP, global 100/h) are stricter on the actual abuse paths and remain the real control; the Cloudflare layer adds nothing needed (free-plan rate rules not required). 429 from nginx has no JSON body: SPA must tolerate a plain 429 (check `apiFetch` error path in the plan; minor).

- Enabling nginx: `ln -s ../sites-available/birja.nist.one /etc/nginx/sites-enabled/` (new file only; do not edit `nist.one`/`default`/`lib.nist.one`), `nginx -t`, `systemctl enable --now nginx`. 80/443 are free [VERIFIED `ss -ltn`]. ## Common Pitfalls

1. **Deploying an empty `main`** - `main` = "Add base files". Prevention: release merge before first deploy; deploy.sh prints the SHA and refuses if `backend/` is missing.
2. **add_header inheritance** - see section 6; smoke-test headers on three paths.
3. **526/521 after cutover** - 526: cert invalid/expired or wrong SAN; 521: nginx not enabled or reload failed. Prevention: issue + install cert and `nginx -t` before creating the DNS record.
4. **Every user shares one rate-limit bucket** if `--forwarded-allow-ips` doesn't contain the actual peer (the gateway). Prevention: pinned subnet + the IP verification task; check the real peer once with `docker compose exec backend` logging or a temporary debug on the test stack, not in prod.
5. **Resend sending domain mismatch** - `EMAIL_FROM` must be on a verified Resend domain; otherwise 403 and users see "temporarily unavailable". The app retries 3x then fails; check logs (no codes logged in prod; error lines only).
6. **Secrets in logs via compose** - `docker compose config`, `docker inspect`, `set -x`. The deploy script must not run with `-x` and must not print env.
7. **acme.sh `*` in directory names** - always single-quote `'*.nist.one'` and use the `--ecc` flag on every later command for this cert (`--renew`, `--install-cert`, `--list` uses it automatically).
8. **Forced issue loops** - one shot; read the error (ZeroSSL limits unverified).
9. **Dev and prod DNS names** - dev stack listens only on 127.0.0.1:5173/8000; prod on 127.0.0.1:18000; no overlap. `ng serve` on 0.0.0.0:4200 is firewalled by ufw (INPUT DROP) - not our concern, mention to user.
10. **nginx reload with stale snippet** - `cloudflare-ips.sh` must not leave an empty/invalid snippet (that would make `real_ip` trust nothing -> rate-limit collapses to one bucket, or break `nginx -t`).

## Phase Goal

**As a** friend trying YokaiExchange, **I want to** sign in with a code sent to my email and stay signed in, **so that** I get my $10,000.00 practice account exactly once and can come back to it without a password.

<objective>
Slice 3 of sign-in: proving the code now actually signs the user in. verify-code opens a server-side session (an `auth_sessions` row plus a hashed refresh token) and sets the three cookies; `GET /api/v1/me` returns the signed-in user and cash. This is the backend half of "user lands signed in" (SC2) and the base for "stays signed in" (SC4).

Purpose: Session state lives in Postgres (source of truth, revocable), the access JWT carries the session id so every request checks it, and the auth split is right: 401 for not authenticated, 403 (CSRF) for not allowed.
Output: `models/auth.py`, migration `0003`, JWT/cookie helpers, `CurrentUserDep`, `GET /me`, `JWT_SECRET` setting.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser cookie jar -> API | Cookies are attacker-controllable input on every request |
| app -> Postgres session tables | Revocation state and refresh hashes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-19 | Spoofing | JWT forgery / alg confusion | mitigate | PyJWT with `algorithms=["HS256"]` pinned, required claims, iss/aud/typ checks, secret >= 32 chars and distinct from the OTP secret; tests for none/HS512/wrong secret/expired/missing claims |
| T-02-20 | Spoofing | stolen access cookie after sign-out | mitigate | JWT carries `sid`; `get_current_user` requires a non-revoked `auth_sessions` row on every request; test with revoked_at set |
| T-02-21 | Information disclosure | token theft via XSS | mitigate | Access and refresh cookies HttpOnly; nothing in localStorage; React default escaping |
| T-02-22 | Tampering | CSRF on cookie auth | mitigate | SameSite=Strict on all cookies + double-submit CSRF on every POST (02-02); csrf rotated at sign-in |
| T-02-23 | Information disclosure | refresh token at rest | mitigate | Only sha256 hex stored (`token_hash`, 64-char CHECK); raw value only in the HttpOnly cookie scoped to `/api/v1/auth/refresh`; test asserts raw value absent from DB |
| T-02-24 | Elevation of privilege | mixing user and session ids | mitigate | Query requires `users.id = sub AND auth_sessions.id = sid AND auth_sessions.user_id = users.id`; cross-user test |
| T-02-25 | Information disclosure | access cookie lifetime longer than JWT | accept | Cookie Max-Age 30 d only keeps an expired JWT around for logout; the JWT `exp` (15 min) is enforced on every protected route |
</threat_model>

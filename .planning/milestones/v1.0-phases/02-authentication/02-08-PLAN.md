## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app -> api.resend.com | Outbound call carrying the API key and the code |
| .env -> container env | Secret enters the process; compose can echo it via `config`/`inspect` |
| public repo / CI logs | Anything committed or printed in CI is public |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-45 | Information disclosure | Resend API key | mitigate | SecretStr + repr=False + hide_input_in_errors; only in local git-ignored `.env`; `.env.example` empty; `git grep` check for `re_...`; tests use `dummy-key-not-real`; never `docker compose config`/`inspect` (D-02) |
| T-02-46 | Information disclosure | code/email in logs | mitigate | ResendSender logs only status; caplog test scans all records for code, key and address; console backend refused when ENV=prod |
| T-02-47 | Denial of service | Resend outage / rate limit | mitigate | 10 s timeout, max 3 attempts with exponential backoff + jitter, retry only 429/5xx/network, honor retry-after (capped); failures logged and swallowed (user can request a new code) |
| T-02-48 | Tampering | duplicate sends on retry | mitigate | One Idempotency-Key per send reused across retries; test asserts the same key on every attempt |
| T-02-49 | Spoofing | phishing look-alike sender | transfer | Sender domain verified in Resend with SPF/DKIM (user's DNS, D-01); EMAIL_FROM must use that domain |

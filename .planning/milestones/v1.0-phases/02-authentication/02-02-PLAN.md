## Phase Goal

**As a** friend trying YokaiExchange, **I want to** sign in with a code sent to my email and stay signed in, **so that** I get my $10,000.00 practice account exactly once and can come back to it without a password.

<objective>
Slice 1 of sign-in: a user (via Swagger at /docs or any client) asks for a code and the code is "emailed" through the dev console sender. Includes the full OTP store semantics (single use, 10-minute TTL, 5-attempt kill, race-free verify) because verify-code in 02-03 builds on it, plus CSRF protection on every auth POST from day one (CLAUDE.md: every state-changing request).

Purpose: The first real backend capability of the phase, built so the enumeration-safe response (AUTH-01) holds by construction: request-code never touches the users table.
Output: `services/otp.py`, `services/email.py` (console), `services/auth.py` (`request_code`), `api/v1/auth.py` (2 routes), CSRF helpers, OTP secret setting, test fixtures.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> POST /auth/request-code | Untrusted email input and untrusted origin |
| app -> Redis | OTP state held in a shared, non-authoritative store |
| app -> container logs | Dev console sender writes the code to logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Information disclosure | request-code (account enumeration) | mitigate | No user lookup at all in `request_code`; identical 202 body for every email; send happens in BackgroundTasks after the response; test asserts identical bodies |
| T-02-06 | Spoofing | OTP brute force | mitigate | Atomic Lua attempt counter (max 5, counted before compare), key deleted on the 5th wrong attempt, concurrency test proves <= 5 attempts |
| T-02-07 | Tampering | concurrent reuse of one code | mitigate | Lua compare-and-delete consume; test: 5 parallel verifies -> exactly one True |
| T-02-08 | Information disclosure | OTP at rest in Redis | mitigate | Only HMAC-SHA256(server secret, email+code) stored; key name is an HMAC of the email; secret is SecretStr, >= 32 chars, placeholder refused in prod |
| T-02-09 | Tampering | CSRF on auth POSTs | mitigate | Double-submit `yk_csrf` cookie + `X-CSRF-Token` header compared with `hmac.compare_digest`; SameSite=Strict; 403 on mismatch; tests for missing/mismatch/no-cookie |
| T-02-10 | Information disclosure | console sender logs code + email | accept (dev only) | CLAUDE.md permits a console backend in local dev; 02-08 adds a validator that refuses the console backend when ENV=prod |
| T-02-11 | Denial of service | Redis outage | mitigate | RedisError -> 503 + Retry-After instead of 500 stack traces; no secret or internals in the body |
| T-02-12 | Denial of service | email bombing via request-code | mitigate (02-06) | Rate limits per email, per IP and global are added in 02-06 before the phase ships |
</threat_model>

# Birja 0.6.1 — Legacy portfolio upgrade compatibility

A configured v0.4.0 database could migrate from0008 to0023 but refuse the final
permission check, keeping application writers stopped. Its inherited runtime
permissions were absent from the finite bootstrap allowlist.

This patch recognizes only the independently reproduced legacy permission state
paired with private defaults. Existing normalization installs the same canonical
runtime permissions. Schema, final permission fingerprints, historical contracts,
financial records, dependency versions and stock activation gates stay unchanged.
Current recovery-source bindings follow the reviewed validator changes.

Genuine isolated PostgreSQL regression checks cover original finances/identities,
normalization, repeatability and refusal of mismatched permissions/defaults.
Hosted CI and production outcomes are recorded in the shipping receipt.
